Исследование управления силой стохастичности (`eta`) в SDE-сэмплерах для flow-matching моделей
при малых бюджетах NFE (6–15 шагов).

Это продолжение двух прежних работ, опубликованных в
[adaptive-step-samplers](https://github.com/YakovSava/adaptive-step-samplers)
([DOI](https://doi.org/10.5281/zenodo.23529356)):

1. Бесплатная локальная оценка ошибки по разности предиктора и корректора, использованная для
   адаптивного шага.
2. Открытая сила стохастичности SA-Solver, включая управление шумом по ошибке (`response` ≠ 0),
   которое оказалось отрицательным результатом.

В этом репозитории проверяется другой механизм: распределение шума по шагам в соответствии с
локальной кривизной траектории.

## Мотивация

`sa_solver` в ComfyUI жёстко задаёт силу стохастичности постоянной `eta = 1.0` внутри
фиксированного окна 20–80 %. Прежняя работа открыла `eta` и показала, что `eta = 1.6–1.8`
покупает текстуру ценой макрогеометрии, причём «курс обмена» резко падает после `1.8`. И
константа, и окно подбираются вручную и не учитывают, что на самом деле происходит с траекторией.

Прежняя попытка сделать шум адаптивным управляла им напрямую по бесплатной оценке ошибки
предиктора–корректора (`pc_error`). Во всех тестах она в пределах шума совпала с простым
снижением `eta` на ту же среднюю величину. Это значит, что важна была *величина* шума, а
управление пропорционально ошибке ничего не добавило.

## Гипотеза

Открытый вопрос другой: **не сколько шума, а где вдоль траектории он вносится.** Шум, добавленный
там, где поле скоростей жёсткое (высокая кривизна), может усиливаться в геометрическую ошибку, а
тот же шум на гладком участке может превращаться в текстуру. Тогда перераспределение фиксированного
бюджета шума по шагам в соответствии с локальной кривизной должно улучшить компромисс
геометрия/текстура по сравнению с равномерной `eta` при том же бюджете.

Это иной механизм, чем `response` ≠ 0, и до этой работы он не проверялся (результаты ниже). Знак
зависимости (больше шума на жёстких шагах или на гладких) не был известен заранее и входил в то,
что должны были определить эксперименты.

## Метод

На каждом шаге `i` сэмплер уже вычислил модель и располагает производной
`d_i = (x_i - denoised_i) / sigma_i`. Локальная кривизна —

```
kappa_i = rms(d_i - d_{i-1}) / |sigma_i - sigma_{i-1}|
```

это величина, которую записывает Trajectory Probe из прежней работы; она стоит **ноль
дополнительных вызовов сети**. Мощность шума на шаге от `i` к `i+1`:

```
tau_i^2 = eta_bar^2 * w_i * c_i      внутри окна шума, 0 вне его
w_i     = clamp((kappa_i / reference_i)^exponent, 1/spread, spread)
```

где `reference_i` — скользящее среднее прошлой кривизны, `eta_bar` — номинальная сила, а `c_i` —
коэффициент сохранения бюджета (см. ниже). Управление причинное: оно использует только
информацию, доступную после вычисления на шаге `i`.

### Контроль, который важен: равный бюджет шума

Отрицательный результат выше смешивал два фактора: *сколько* и *где*. Чтобы не повторить это,
каждый адаптивный запуск сравнивается с запуском с равномерной `eta` и **тем же интегральным
бюджетом шума**, например совпадающим по `sum(tau_i^2 * h_i)` по окну (где `h_i` — шаг по
log-SNR). Только выигрыш при равном бюджете подтверждает гипотезу о перераспределении.

### Сравниваемые варианты

Все варианты — настройки одной ноды `Flow-SDE Sampler` (`signal`, `exponent`,
`conserve_budget`); см. [Реализация](#реализация).

| Вариант | Настройки |
| --- | --- |
| `sa_solver` | Базовый вариант ComfyUI; побитово воспроизводится при `eta = 1.0`, `exponent = 0` |
| `uniform` | `exponent = 0`, `eta` 1.6–1.8 (подобранная база из прежней работы) |
| `uniform-matched` | `exponent = 0`, `eta` подобрана так, что `eta^2 * sum(h)` равно реальному бюджету адаптивного запуска. При включённом `conserve_budget` это просто `uniform` с той же `eta` |
| `curvature-online` | `signal = curvature`, `exponent > 0` (больше шума на жёстких шагах) |
| `curvature-online, inverted` | `signal = curvature`, `exponent < 0` (больше шума на гладких шагах) |
| `pc-error-online` | `signal = pc_error`, для сравнения с прежним отрицательным результатом |
| `static-profile` | Неравномерный график `tau` по среднему профилю кривизны, одинаковый для всех сэмплов. **Пока не реализован** |

`static-profile` выясняет, важна ли вообще *онлайн*-адаптация или фиксированный неравномерный
график уже даёт эффект. Прежнее разложение дисперсии (`analyze_dumps.py` в прежнем репозитории)
измеряет, какая доля сигнала объясняется одним номером шага, а какая — особенностями конкретного
сэмпла, и определяет, сколько запаса остаётся у онлайн-управления.

## Реализация

```
noise_allocation.py   NoiseAllocator: tau по шагам из сигнала curvature / pc_error
sampler.py            sample_flow_sde: цикл SA-Solver с tau от аллокатора
nodes.py              нода ComfyUI "Flow-SDE Sampler"
metrics.py            метрики геометрии / текстуры, преимущество над границей, bootstrap
profiles.py           граф, разрешение, cfg и пулинг метрик для каждой модели
run_experiment.py     управляет ComfyUI по HTTP API и печатает сравнение
export_results.py     пишет все метрики по сэмплам и сводную таблицу в results/
build_survey.py       собирает набор картинок и ключи для опроса людей в survey/
results/              samples.csv (строка на изображение) и summary.csv (строка на модель, NFE, вариант)
tests/                модульные тесты (pytest)
```

Установка: клонировать в `ComfyUI/custom_nodes/` и перезапустить ComfyUI. Дополнительных
зависимостей нет. Нода находится в `sampling/custom_sampling/flow_sde`.

| Параметр | Смысл |
| --- | --- |
| `eta` | Номинальная сила стохастичности `eta_bar` |
| `stochastic_start`, `stochastic_end` | Окно шума, как в `sa_solver` (по умолчанию 0.2–0.8) |
| `signal` | `curvature` (бесплатно, из соседних производных) или `pc_error` (бесплатно, разность предиктора и корректора) |
| `exponent` | Степень, в которую возводится `signal / running_reference`. `0` отключает адаптацию; знак выбирает больше шума на жёстких или на гладких шагах |
| `conserve_budget` | Масштабирует последующие шаги так, чтобы `sum(tau_i^2 * h_i)` по окну равнялась `eta^2 * sum(h_i)`. Остаток поглощает последний шаг окна |
| `spread` | Вес ограничивается диапазоном `[1/spread, spread]` |
| `smoothing` | Коэффициент EMA для скользящего опорного значения |
| `tau_max` | Жёсткий предел для `tau` (из-за отсечения часть бюджета может остаться неизрасходованной) |

Вес действует на мощность шума `tau^2`, а не на `tau`, потому что бюджет измеряется в
`tau^2 * h`. Стоимость — ровно 1 NFE на шаг.

### Тесты

```
venv/Scripts/python.exe -m pytest custom_nodes/flow-sde-research/tests
```

Запускать из корня ComfyUI. Тесты проверяют, что `exponent = 0` побитово воспроизводит
`sa_solver` на 6, 10 и 15 шагах (максимальная абсолютная разность `0`), что NFE равно числу шагов
в адаптивных запусках, что реально израсходованный бюджет сохраняющего запуска равен бюджету
равномерного, а также инварианты аллокатора (окно, границы, отсечение, знак экспоненты). Тесты
сэмплера используют синтетическую flow-модель, поэтому они доказывают корректность механизма и ничего
не говорят о качестве изображений.

### Запуск эксперимента

При запущенном ComfyUI (и после правки имён модели, LoRA, текстового энкодера и VAE в
`profiles.py` под вашу установку). `--model` выбирает профиль (`anima` по умолчанию, `flux3` или
`moss`):

```
venv/Scripts/python.exe custom_nodes/flow-sde-research/run_experiment.py \
    --prompts flat face --seeds 42 1337 --budgets 10 --variants sa_solver uniform_e17 curv_p1
```

Латенты и изображения пишутся в `output/flow_sde/` (`output/flow_sde_flux3/` и
`output/flow_sde_moss/` для других моделей); завершённые задания пропускаются, поэтому прерванный
запуск продолжается. `--analyse-only` пересчитывает отчёт по существующим файлам, `--report FILE`
сохраняет метрики по сэмплам в JSON.

Отчёт выводит среднюю геометрию, текстуру и разрыв текстуры до сошедшегося 30-шагового эталона
для каждого варианта, а также **преимущество по текстуре над uniform-границей**: разность между
текстурой варианта и текстурой, которую имел бы сэмплер с равномерной `eta` (`uniform_e14`,
`uniform_e17`, `uniform_e20`) при той же геометрии (линейная интерполяция), с 95 % bootstrap
доверительным интервалом по парам (промпт, seed). Вариант, который просто движется вдоль кривой
`eta`, получает ноль; лучший компромисс даёт значение выше нуля. Если геометрия варианта выходит
за диапазон равномерных запусков, выводится `n/a`.

### Сохранённые метрики

`results/samples.csv` содержит строку на каждое сгенерированное изображение (модель, версия
ComfyUI, вариант, промпт, seed, NFE, геометрия, текстура, разрыв текстуры, тип эталона
геометрии). `results/summary.csv` содержит средние по (модель, NFE, вариант) и преимущество по
текстуре над uniform-границей с 95 % bootstrap-интервалом. Оба файла пересоздаются из сохранённых
латентов командой `venv/Scripts/python.exe custom_nodes/flow-sde-research/export_results.py`.
Интервалы в CSV могут отличаться от таблиц README в последней цифре, потому что bootstrap
перебирает пары в другом порядке; точечные оценки совпадают. Строки Anima получены на ComfyUI
0.31.1, остальные на 0.42.5 (колонка `comfyui_version`), а колонка `geometry` у Flux 3 отсчитана
от `euler` с тем же числом шагов, тогда как у двух других — от 100-шагового запуска.

Измеренная стоимость на RTX 5060 (8 ГБ) при 768×1024: около 0.65 с на шаг для Flux 3 Klein и
0.9–1 с на шаг для Anima и MOSS-Image. 100-шаговый эталон геометрии (около 90 с) и 30-шаговый
эталон текстуры (около 25 с) на каждую пару (промпт, seed) составляют заметную часть стоимости.
Полные прогоны 16 пар × 5 бюджетов × 8 вариантов заняли 70 мин (Flux 3 Klein) и 150 мин
(MOSS-Image); Anima запускалась в два этапа по 57 и 101 мин.

## Протокол оценки

Протокол следует прежней работе, чтобы числа оставались сопоставимыми.

- **Модели:** Anima (flow-matching DiT), 768×1024, cfg 5.0, планировщик `normal`; Flux 3 Klein
  (int8-чекпоинт), 768×1024, cfg 1.0, планировщик `normal`, VAE FLUX.2 (см. профиль Flux 3
  ниже); и MOSS-Image SFT (int8-чекпоинт), 768×1024, cfg 3.0, планировщик `normal`, VAE FLUX.2,
  текстовый энкодер Qwen3.5-9B, негативный промпт `worst quality, bad anatomy`. MOSS-Image
  использует протокол Anima без изменений (100-шаговый эталон `euler`) с пулингом 4×.
- **Бюджеты:** 6, 8, 10, 12, 15 NFE, только сэмплеры с 1 NFE на шаг.
- **Геометрия** (меньше — лучше): RMS-отклонение от эталона после усредняющего пулинга в
  латентном пространстве (8× для Anima). Для Anima эталон — 100-шаговый запуск `euler`.
- **Текстура:** RMS высокочастотного остатка (латент минус его версия с пулингом 8×). Приводится
  как абсолютное значение и как разрыв до сошедшегося эталона, здесь 30-шагового `sa_solver`
  (прежняя работа усредняла шесть стохастических сэмплеров, поэтому абсолютные разрывы напрямую
  несопоставимы).
- **Промпты и seed:** четыре класса промптов прежней работы (flat, face, fur, grid), seed больше,
  чем исходные 2, чтобы различия можно было проверять на фоне разброса между seed.
- **Профиль Flux 3.** Два намеренных отступления от протокола Anima:
  1. *Эталон геометрии.* 100-шаговый запуск `euler` **не** является сошедшимся эталоном для этого
     чекпоинта: результаты ODE на 10 и 100 шагах различаются примерно как несвязанные
     изображения (RMS после пулинга 0.51 для одного промпта и 0.54 для другого, против 0.016
     между 50 и 100 шагами на втором), потому что композиция меняется с числом шагов. Это
     согласуется с дистиллированным по шагам чекпоинтом, но это вывод из поведения сэмплирования,
     а не из описания модели. Поэтому геометрия измеряется относительно детерминированного
     запуска `euler` **с тем же числом шагов и seed**, то есть это отклонение, вызванное шумом, а
     не ошибка относительно предела. Значения геометрии Flux 3 несопоставимы со значениями Anima.
  2. *Пулинг.* Латент FLUX.2 имеет пространственное сжатие 16× вместо 8×, поэтому пулинг равен
     4×, чтобы сохранить тот же размер в пикселях.
- **Отчётность:** средние с доверительными интервалами; различие считается установленным, только
  если оно превышает разброс между seed. Отрицательные результаты публикуются.

бюджета шума по локальной кривизне, в любую сторону, не улучшило компромисс геометрия/текстура
относительно равномерной `eta` на 6–15 NFE на Anima. Единственный кандидат, заслуживающий
продолжения, — `pce_m1` на самом малом бюджете (+0.0084, около половины диапазона текстуры,
который охватывает равномерная `eta` 1.4–2.0 на 6 NFE), потому что это единственный результат,
выдерживающий собственный интервал; чтобы считать его реальным, нужно больше сэмплов.

Оговорки:

- Одно `eta_bar` (1.7), `exponent = ±1`, вес ограничен `[1/3, 3]`. Более сильное воздействие,
  другое базовое `eta` или другое опорное значение (`smoothing`) могут вести себя иначе; ничего
  из этого не пробовалось.
- Отрицательный результат при n = 16 исключает лишь эффекты, превышающие полуширину интервала
  (около 0.002–0.03 единиц текстуры в зависимости от бюджета и варианта).
- Абсолютные значения геометрии примерно в 2.3 раза больше значений для тех же сэмплеров в
  прежней работе, хотя порядок (`euler` хуже `sa_solver`) тот же. Скорее всего, настройки метрики
  или эталон изменились между двумя кодовыми базами; не сравнивайте абсолютные числа между двумя
  репозиториями.
- `ode` на 10 шагах показан только для справки и лежит вне диапазона границы.
- Геометрия и текстура — прокси в латентном пространстве, не проверенные на соответствие
  человеческому восприятию.
- Эти запуски выполнены на ComfyUI 0.31.1. После обновления до 0.42.5 (нужного для Flux 3)
  детерминированный `euler` даёт побитово тот же результат, но стохастические сэмплеры при том же
  seed дают другие реализации шума, поэтому запуски Anima из двух версий нельзя смешивать в одном
  парном сравнении. Причина не исследовалась.

### Flux 3 Klein

Условия: int8-чекпоинт Flux 3 Klein, 768×1024, cfg 1.0, планировщик `normal`, ComfyUI 0.42.5, 4
класса промптов × 4 seed (16 парных сэмплов) на каждом из бюджетов 6, 8, 10, 12 и 15 NFE; около
0.65 с на шаг. `eta_bar = 1.7`, `exponent = ±1`, бюджет сохранён. Геометрия — отклонение от
запуска `euler` с тем же бюджетом (см. протокол).

**Преимущество по текстуре над uniform-границей** (точечная оценка и 95 % bootstrap ДИ; `*`
отмечает интервал, не содержащий ноль):

| Вариант | 6 NFE | 8 NFE | 10 NFE | 12 NFE | 15 NFE |
| --- | --- | --- | --- | --- | --- |
| `curv_p1` | −0.0017 [−0.0023, −0.0011] * | −0.0025 [−0.0040, −0.0011] * | +0.0009 [−0.0009, +0.0029] | +0.0003 [−0.0024, +0.0031] | +0.0049 [+0.0003, +0.0096] * |
| `curv_m1` | +0.0045 [+0.0034, +0.0055] * | +0.0030 [+0.0012, +0.0051] * | −0.0043 [−0.0073, −0.0013] * | −0.0034 [−0.0058, −0.0013] * | −0.0049 [−0.0101, −0.0004] * |
| `pce_p1` | −0.0016 [−0.0021, −0.0012] * | −0.0041 [−0.0053, −0.0027] * | −0.0113 [−0.0151, −0.0074] * | −0.0084 [−0.0122, −0.0044] * | −0.0100 [−0.0142, −0.0058] * |
| `pce_m1` | +0.0041 [+0.0028, +0.0053] * | +0.0042 [+0.0034, +0.0051] * | +0.0090 [+0.0058, +0.0115] * | +0.0042 [+0.0016, +0.0065] * | +0.0110 [+0.0052, +0.0167] * |

**Прочтение.**

- **Распределение по ошибке даёт согласованный эффект.** `pce_m1` (больше шума там, где
  бесплатная ошибка предиктора–корректора мала, и меньше там, где она велика) положителен с
  интервалом, исключающим ноль, на всех пяти бюджетах, а его зеркальный вариант `pce_p1`
  отрицателен на всех пяти. Такую зависимость от дозы трудно объяснить случайностью. Размер
  скромный: на 15 NFE `pce_m1` выигрывает 0.0110 единиц текстуры, около 90 % той текстуры,
  которую равномерная `eta` покупает при росте с 1.4 до 2.0 (0.7145 → 0.7268); на 10 NFE это
  около половины такого диапазона. Относительно самого значения текстуры (около 0.7) это 1–2 %.
- **Кривизна — нестабильное управление.** `curv_m1` положителен на 6 и 8 NFE и отрицателен на 10,
  12 и 15; у `curv_p1` картина обратная. Знак эффекта зависит от бюджета, поэтому ни одно
  направление правила по кривизне не помогает на всех бюджетах. Исходная гипотеза о кривизне
  по-прежнему не подтверждена; результат на Flux 3 держится на сигнале ошибки.
- **Закон распределения не универсален.** Та же настройка `pce_m1` на Anima неубедительна:
  положительные точечные оценки на 6 и 10 NFE, ни одна не надёжна, и другой знак на остальных
  бюджетах. Каков бы ни был механизм, на этой модели он заметно сильнее, чем на Anima, что на
  вопрос о переносе отвечает «требуется калибровка под каждую модель», а не «универсально».

Оговорки, специфичные для этого результата:

- Текстура — энергия высоких частот в латентном пространстве. Она не отличает настоящую мелкую
  детализацию от остаточного шума, а шум, внесённый поздно на траектории, тоже её повышает.
  Выборочная проверка кропов на 15 NFE для двух промптов и одного seed не показала заметного
  зерна у `pce_m1` по сравнению с равномерной `eta`, но выборочная проверка — не тест.
  Исследование на людях, упомянутое во вторичной задаче, теперь самый информативный следующий
  эксперимент.
- Ось геометрии поменяла смысл (отклонение от детерминированного запуска с тем же бюджетом), а
  чекпоинт, вероятно, дистиллирован по шагам, поэтому граница построена по модели, чей отклик на
  `eta` гораздо более плоский, чем у Anima (текстура 0.7097 → 0.7274 при `eta` 1.4 → 2.0 на 10
  NFE). На плоской границе небольшие абсолютные различия весят больше.
- Выполнено 20 сравнений без поправки на множественную проверку. Знакопостоянный узор `pce` от
  неё не зависит, а отдельные значимые интервалы `curv` — возможно, зависят.
- Одно `eta_bar`, одна величина `exponent`, один чекпоинт.

### MOSS-Image

Условия: int8-чекпоинт MOSS-Image SFT, 768×1024, cfg 3.0 с обычным classifier-free guidance
(без skip-layer guidance), планировщик `normal`, ComfyUI 0.42.5, 4 класса промптов × 4 seed (16
парных сэмплов) на каждом из бюджетов 6, 8, 10, 12 и 15 NFE; около 0.9 с на шаг. `eta_bar = 1.7`,
`exponent = ±1`, бюджет сохранён. В отличие от Flux 3, этот чекпоинт не дистиллирован по шагам, и
100-шаговый запуск `euler` пригоден как эталон (RMS после пулинга между 50 и 100 шагами: 0.16 и
0.05 для двух промптов), поэтому протокол Anima применяется как есть. Разработчик рекомендует не
менее 50 шагов и не менее 1 Мпикс; в этом эксперименте 6–15 шагов и 0.79 Мпикс, то есть вне
предполагаемого режима.

| `curv_m1` | +0.0029 [+0.0015, +0.0042] * | +0.0015 [−0.0009, +0.0034] | −0.0029 [−0.0086, +0.0021] | −0.0045 [−0.0095, +0.0020] | −0.0029 [−0.0067, +0.0013] |

**Прочтение.**

- **Сигнал ошибки важен в одном направлении.** Концентрация шума на шагах с *высокой* ошибкой

  вредна именно подача шума туда, где решатель и так неточен, а перенос шума в другое место
  помогает лишь слегка. Это прочтение трёх наборов данных, а не проверенный механизм.
- **На 6 NFE аллокации почти нечего перераспределять.** `pce_p1` и `pce_m1` там ложатся на
  равномерную `eta` (геометрия 0.4862 и 0.4864 против 0.4864), как и ожидается, когда окно шума
  содержит лишь несколько шагов.
- **Кривизна снова не показывает устойчивого эффекта.** Два значимых интервала на 6 NFE с
  противоположными знаками для двух направлений и ничего согласованного выше.

### По моделям

Преимущество по текстуре у вариантов `pc_error` над uniform-границей, подсчитанное по пяти
бюджетам (6, 8, 10, 12, 15 NFE):

| Модель | `pce_m1` положителен / значимо положителен | `pce_p1` отрицателен / значимо отрицателен |
| --- | --- | --- |
| Anima | 2 / 1 | 2 / 0 |
| Flux 3 Klein | 5 / 5 | 5 / 5 |
| MOSS-Image | 5 / 1 | 4 / 4 |

(Каждая ячейка — число бюджетов из пяти с точечной оценкой указанного знака / с 95 % интервалом,

## Вторичная задача

- **Перенос на другую flow-matching модель.** Выполнен для Flux 3 Klein (см. выше): эффект не
  универсален. MOSS-Image (другая архитектура: DiT на 5 млрд параметров, текстовый энкодер
  Qwen3.5-9B, общий только VAE FLUX.2) тоже выполнен; направление эффекта `pc_error` совпадает с
  Flux 3, но размер гораздо меньше.
- **Проверка метрик по человеческому восприятию.** Набор изображений и ключи ответов подготовлены
  (см. [Материалы для опроса людей](#материалы-для-опроса-людей)); ответы собираются, анализ пока не проводился.
  Исследование спрашивает, какое из двух изображений выглядит сгенерированным ИИ, чтобы проверить,
  согласуются ли собственные метрики геометрии и текстуры с человеческим восприятием, поскольку на
  них держатся все количественные утверждения. С учётом результата Flux 3 это приоритет: вопрос в
  том, замечает ли человек прирост текстуры `pce_m1`.

## Известные ограничения

- Три модели, у двух из них int8-чекпоинты, и одно `eta_bar`; профиль Flux 3 использует эталон
  геометрии, отличный от двух других.
- Геометрия и текстура — прокси в латентном пространстве, а не проверенные перцептивные метрики.
- Рост `eta` также смещает композицию, поэтому «геометрия» относительно детерминированного
  эталона смешивает структурный ущерб с допустимой вариативностью.

## Связь с прежним репозиторием

Цикл SA-Solver в `sampler.py` адаптирован из `sample_adaptive_sa` в `adaptive-step-samplers`, при
этом контроллер по ошибке заменён на `NoiseAllocator`. Trajectory probe и скрипты анализа не
копировались, и раннер экспериментов от них не зависит: он сохраняет итоговые латенты штатной
нодой `SaveLatent`.
